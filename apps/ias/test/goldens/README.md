# Goldens

Generated by `bun run golden:generate` from Warren's calculator, Warren1001's IAS Calculator at `bcc112d` (v1.2.4, D2R 3.3), including where it differs from the game. Regenerate, never edit.

## Files

- `meta.json`: `upstreamSha`, `gameVersion`, `generatedAt`, `generatorVersion`, `cases` (total) and `casesByKind`.
- `forms.json`: form snapshots stored once, `{ [ref]: { options, visible } }`. Cases share a few hundred distinct forms, so each case references one instead of repeating it.
- `cases/<family>/<character>.jsonl`: one case per line, `{ id, input, form, output }`.

## Case line

- `id`: the six select values in canonical order, `character|wereform|skill|primary|secondary|table`, with `-` for a select that was hidden and never set. Filled fields follow as `|field=value,...`.
- `input`: the 24 controls of `#calculator`, keyed by element id in DOM order, read after the last choice. Select values stay as the page holds them: numbers as strings for character, wereform and table variable (`constants.js:63-95`), names for skills and weapons (`None` is unarmed). Number fields are integers, checkboxes booleans. A hidden control keeps whatever the page left in it.
- `form`: a key of `forms.json`. `options` lists what each select offers after the last choice: hidden options are dropped, disabled dividers read `divider`, repeated options stay (Zeal twice for the Paladin). `visible` lists the visible `#calculator > div` ids.
- `output`: `tables` in page order, each `{ header: [label, "FPA"], rows: [[value, frames], ...] }` as rendered text. The note paragraphs above the tables are not recorded.

## Canonical path

Each case runs in a fresh page with `console.log` neutralized. The generator sets each visible select in the order character, wereform, skill, primary weapon, secondary weapon, table variable, and sends a `change` event even when the value does not change. It then fills the visible number fields, then the visible checkboxes, in DOM order, each with a `change` event. It reads `#tableContainer` right after the last event.

## Case kinds

- `structural`: every configuration the canonical path reaches, with weapons reduced to the first option of each (type, WSM) class per slot, and fields at their defaults.
- `variant`: one per structural case. Each visible field gets a value drawn from `sha256(structural id + "#" + field id)`: number fields within their HTML `min`/`max` (IAS within 0 to 400), checkboxes at 50 %. Only values that differ from the default are filled; a variant with none is omitted.
- `bounds`: for each (character, wereform, skill) group, on the configurations with the first primary and secondary weapon, each visible field at its `min` and at its `max`, one field at a time. A bound equal to the default is the structural case itself.
- `reference`: the Zeal and Smite Paladins that the tests name, with their own weapon (Phase Blade) instead of its class representative (Cutlass).

## Families

- `dual`: a visible secondary weapon other than `None`, or Whirlwind.
- `forms-mercs`: a wereform or a mercenary.
- `single`: everything else.

`dual` wins when a case matches both.
